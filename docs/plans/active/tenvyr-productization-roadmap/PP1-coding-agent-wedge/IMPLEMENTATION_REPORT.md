# PP1 Implementation Report — Coding-Agent Control Plane Wedge

## Summary of Completed Work

1. **Area 1: Worker RuntimeConnection Routing Authority (P0)**
   - Enforced in `validateTaskBatchProposal`: `task.agent` must match the frozen connection selection's expected transport agent (`expectedAgent = matchingSelection.agent ?? toTransportAgent(matchingSelection.name)`). Any mismatch throws `AGENT_NOT_ALLOWED`.
   - Compiler immunity: `compileIterationPlanPatch` derives `step.agent` strictly from the Tenvyr frozen configuration (`expectedAgent`) rather than untrusted planner proposal output.
   - Comprehensive unit tests added in `coordination.spec.ts` verifying rejection of malicious agent bypass attempts.

2. **Area 2: Worker Role Protocol Ownership (P1)**
   - Strict namespacing in `WorkerInvocationInputV1`: worker task input is encapsulated under `taskInput: task.input ?? null` without destructive flattening into top-level protocol fields (`role`, `schemaVersion`, `goal`, `iterationNumber`, `taskId`).
   - Exported typed validator `parseRoleInvocationInput` in `coordination.ts`.
   - Hostile input overwrite test suite verified in `coordination.spec.ts`.

3. **Area 3: Safe Release Dedicated Committed OperatorAction Saga (P1) — final bounded closure**
     - **Durable intent + exactly-one Git owner + ACTIVE-only target ownership:** `OperatorAction` lifecycle `REQUESTED → EXECUTING (processInstanceId+ownerToken/claimedAt via CAS) → REMOVED/PRESERVED/INTERRUPTED/IN_PROGRESS`; duplicate while owner alive (same `processInstanceId`) returns `IN_PROGRESS` and never runs Git; stale `EXECUTING` from dead process may be taken over via CAS to new `processInstanceId`. No DB transaction spans Git. `workspace_release_locks` + `releaseOperationId` are active ownership only: **ONE authoritative terminal transaction** (after the bounded `git worktree list`/`remove` observation) atomically commits `WorkspaceExecution` terminal state + `failureCode`/`hasUncommittedWork` + `releaseOperationId=null` + `workspace_release_locks` deletion + `OperatorAction` terminal outcome. Historical audit remains in `OperatorAction` rows; a new idempotency key can acquire a `PRESERVED`/`FAILED` workspace only after the terminal transaction commits.
     - **Truthful audit + every command finalized:** `truthfulReleaseRefusalOutcome` reads actual durable `WorkspaceExecution` row; every `OperatorAction` identity ends with truthful durable evidence (`REMOVED`/`PRESERVED`/`IN_PROGRESS`/`INTERRUPTED`) or intentionally remains the exact recoverable active/pending operation — never an accidental `REQUESTED` orphan. Preflights finalize newly-created `OperatorAction` as `IN_PROGRESS`/`PRESERVED` before throwing; late-arrival barrier verified. If the authoritative terminal transaction rolls back (real PG failure or injected `terminalShouldFail`), durable state stays `RELEASE_REQUESTED` + `releaseOperationId=A` + `lock A` + `A pending recoverable` (not `INTERRUPTED`), so a **new UUID B can discover/recover exact A**; recovery re-observes filesystem (`ABSENT→REMOVED` without second Git, `REGISTERED→bounded Git`, `UNKNOWN→fail closed`).
     - **Exact authority correlation + single driver:** `WorkspaceExecution.releaseOperationId` added via migration; **before Git** the service proves repository-consistently `action.id == workspace.releaseOperationId && action.action == release-execution-workspace && action.targetId == workspace.id && outcome.pending && phase == EXECUTING && exact ownerProcessId/ownerToken` from the successful CAS claim. `worktreeIsRegistered()` is explicit tri-state (`REGISTERED`/`ABSENT`/`UNKNOWN`); `UNKNOWN` never becomes `REMOVED`; `tryRecoverStaleOperation` branches explicitly on `ABSENT`/`UNKNOWN`/`REGISTERED`. Historical finalized actions never authorize later Git. **Single target-scoped recovery** (`claimReleaseOwnership` + `releaseExecutionWorkspace` + `tryRecoverStaleOperation` + `observeRecoveredRelease`) handles `pending REQUESTED` (B observes A → CAS claim A → Git as A → B `performedByOperationId:A`), `stale EXECUTING`, `recoverable INTERRUPTED` that still owns `RELEASE_REQUESTED`, `terminal/mismatched`, and `already REMOVED` (repair without Git, B `duplicate` with `performedByOperationId:A`, never `executed` as B).
     - **Crash recovery (54 PG tests):** `REQUESTED` before claim → same operation can progress; `EXECUTING` before `RELEASE_REQUESTED` → takeover or `INTERRUPTED`; `RELEASE_REQUESTED` before Git → exact owner recovered; Git-removed before `REMOVED` → `REMOVED` without re-run; `REMOVED` before audit → audit finalized; dirty/operational/unknown → `PRESERVED`; unmatched `RELEASE_REQUESTED` → `RELEASE_UNAUTHORIZED`; terminal → clean → new key → `REMOVED`; orphan terminal locks reconciled; **REQUESTED A + NEW UUID B → A terminal, B `performedByOperationId:A`, Git 1, no orphan**; **Git success + terminal transaction rollback → RELEASE_REQUESTED/lock/A pending, B recovers via ABSENT without second Git**; **REMOVED + pending A → A repaired without Git, B `duplicate` with `performedByOperationId:A`**; **pre-remove `worktree list` UNKNOWN → Git 0, `PRESERVED` `WORKTREE_STATE_UNKNOWN`**; **reconciliation `worktree list` UNKNOWN → no Git, no REMOVED**; **R1/R2/R3/UNKNOWN strict** + **marker-write failure same-process recovery** (dirty `PRESERVED/WORKTREE_DIRTY` + UNKNOWN `PRESERVED/WORKTREE_STATE_UNKNOWN` via `!isActiveToken`), late-arrival, historical, null-path, and pure-read Attention covered.
     - **Attention pure READ:** `AttentionService.attention()`/`GET /workbench/attention` performs **no durable state transition and no filesystem mutation**; terminal `IN_USE → PRESERVED` is via the authoritative run-completion path (`preserveExecutionWorkspaceForRun` in the coordination transaction), not lazy polling; continuation does not depend on Attention. Regression snapshots `workspace/operator` rows, polls Attention `5×`, proves no DB writes and no Git calls; docs (`attention.md`, `implementation-status`) aligned.
     - **Frontend:** `attention/page.tsx` never shows “released safely” unless `REMOVED`; `IN_PROGRESS` → “in progress”, `INTERRUPTED` → “interrupted; retry”, `PRESERVED` refusal → error; unknown state fails closed.
